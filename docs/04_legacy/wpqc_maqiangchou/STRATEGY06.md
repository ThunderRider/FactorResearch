# strategy06.py（V6）详细说明

> 一个脚本，两条选股线，一个决策器，一个可选的风险开关。
> 交易结构不变：**T 日 14:45 买入，T+1 日 11:15 清仓，每日全换手**。

---

## 1. 它解决什么问题

V1 和 V3 是两条**性格相反**的策略：

| | V1（高弹性） | V3（错杀修复） |
|---|---|---|
| 选什么 | 高 RESI（高波动）、量价关系稳 | 缩量、冷门、20 日超跌 |
| 池资金 | 50 / 50 | 30 / 70（偏小盘） |
| 隔夜段 | **−13.9bp**（拖累） | **+6.7bp**（贡献） |
| 擅长 | 同涨同跌、弹性释放 | 分化、错杀修复 |
| 前 10 天贡献 | 97% | 58% |

两条线的持仓重合度只有 **0.3%**，等于两个完全不同的组合。
V6 要回答的是：**今天该用哪一条？**

## 3. 模块逐个讲

### 3.1 取数（复用 `strategy02`）

```python
import strategy02 as PROD
pools = PROD.build_pools(end, workers=4)      # 成分股 + 剔除 ST
bars = PROD.fetch_price(codes, end, fields, chunk_size=200, workers=4)
```

* 字段：`open / close / high / low / volume / total_turnover`；
* 分片 + 线程池 + 3 次重试，3761 只约 7 分钟；
* **加了本地缓存** `eval_out/v6_cache.pkl`，调试时可用 `--reuse-cache` 跳过取数。

### 3.2 每日快照

把 8 根 30 分钟 bar 压成一行，只保留决策需要的时点：

| 时点 | 取什么 | 用途 |
|---|---|---|
| 10:00 | open | 当日开盘（算隔夜跳空） |
| 11:00 / 11:30 | close | 次日 11:15 出场价的近似 |
| 14:00 / 14:30 | close | 尾盘动量、日内位置 |
| 14:30 | volume | 量比（同时刻对比，避开 U 型季节性） |
| 15:00 | close | 当日收盘（算日收益、隔夜起点） |

**关键点**：`reindex` 到"全部交易日 × 全部股票"，停牌日留 NaN。
否则 `shift(-1)` 会跳到"下一个有数据的日子"，收益口径会悄悄变成"持有了好几天"。

### 3.3 V1 线（两段式）

```python
# 大盘池：先按 RESI 降序取 10，再按 coef_std 升序取 3
# 小盘池：先按 coef_std 降序取 10，再按 RESI 升序取 3
```

因子定义（窗口 40 根 30 分钟 bar ≈ 5 个交易日）：

* `RESI`：`ln(典型价)` 做 40 根线性回归后的**残差**，再取 40 根标准差 → "去掉趋势后的波动幅度"；
* `coef_std`：`ln(价格)` 与 `ln(成交量)` 的 40 根滚动相关，再取 40 根标准差 → "量价关系的稳定度"。

> 注意：这两个因子有已知缺陷（RESI 本质是波动率、coef_std 对符号不敏感），
> 但 V1 作为"高弹性"代表仍有价值——V6 只是**偶尔**用它，不是主力。

### 3.4 V3 线（三因子）

```python
score = −z(vol_ratio) + z(amihud[T−1]) − z(ret_20d)      # 池内标准化，截尾 ±3
picks = 每池 score 前 4
```

| 因子 | 定义 | 经济含义 |
|---|---|---|
| `vol_ratio` | 14:30 成交量 / 过去 20 日同时点均量 | 缩量（关注度低） |
| `amihud[T−1]` | 20 日平均(\|日收益\|/成交额)，**滞后一天** | 冷门、流动性差 |
| `ret_20d` | 今日 14:30 收盘 / 20 交易日前 14:30 收盘 − 1（取负） | 超跌反转 |

前置**可交易过滤**：

```python
|当日 14:30 涨幅| < 9.5%   # 剔除涨停/跌停
14:30 成交量 > 0           # 剔除停牌
20 日均成交额 > 5000 万    # 剔除流动性太差
```

> **为什么 amihud 要滞后一天？** 当日 amihud 用到 15:00 收盘价和全天成交额，
> 而决策在 14:45——这是 15 分钟前视。滞后一天后，回测反而更好（+2.5pp），
> 因为它本质是"冷门溢价"，不需要当天信息。

### 3.5 决策器（核心）

```python
disp = 全池当日 ret_5d 的截面 IQR = Q75 − Q25
pct  = disp 在过去 120 个交易日的扩展分位（expanding）
use_v1 = pct < 0.5
```

**为什么用 IQR 而不是标准差？**
`ret_5d` 的截面分布有厚尾（涨跌停、停牌复牌），标准差会被极端值主导；
四分位距只看中间 50% 的股票，更稳定。

**为什么是 5 日而不是 20 日？**
实测 `iqr20` 这一族样本外全负，`iqr5` 这一族 6/6 全正。
经济解释：5 日 IQR 刻画的是"最近一周的分化程度"，
20 日 IQR 掺入了中期趋势，与"分化"不是一回事。

**为什么阈值 0.5？**
0.4 / 0.5 / 0.6 三档都测过，0.5 与 0.6 的样本外都不错（11.2% / 9.9%），0.4 明显差（2.8%）。
选 0.5 是因为它最"中性"（中位数切分），不是因为它最优。

### 3.6 趋势门（可选）

```python
trend = 全池当日 ret_20d 的截面中位数
tpct  = trend 的 120 日扩展分位
tpct > 0.5 → 仓位 ×1.0；否则 → 仓位 ×0.5
```

**它不是 alpha，是风险旋钮，而且在完整样本上并不划算。**

| 方案 | 净年化 | Sharpe | MDD |
|---|---|---|---|
| V6 决策器 | **13.68%** | **0.88** | −21.46% |
| V6 决策器 + 趋势门 | 10.36% | 0.75 | −21.46% |

去掉预热期的子样本上，趋势门能把 MDD 压到 −8.7%；但完整样本的最大回撤
发生在 2024 年初的小盘股灾，那时还在"前 120 天预热期"、趋势分位尚未成形，门控不起作用。

> **默认建议 `--mode decision`（不开趋势门）**。

### 3.7 权重

```python
池预算 = 0.96 × 池占比 × 档位（1.0 或 1/16）× 趋势门（1.0 或 0.5）
单票权重 = 池预算 / 持仓数
若单票 > 19% → 压到 19%，超额在池内其他票上再分配
```

| 线 | 池占比（大盘/小盘） | 每池只数 | 高档单票 | 低档单票 |
|---|---|---|---|---|
| V1 | 50 / 50 | 3 | 16.0% | 1.0% |
| V3 | 30 / 70 | 4 | 7.2% / 16.8% | 0.45% / 1.05% |

## 8. 使用边界（重要）

### 8.1 这个结论有多可靠

* **决策器**：全样本在随机安慰剂分布的第 87.8 分位（不显著），样本外 99.1 分位（显著）；
  24 个参数格子里只有 7 个赢过 V3。**属于"值得跟踪"，不属于"可以上线"。**
* **趋势门**：确定性的降仓，没有 alpha，但对回撤有效。
* **V3 选股**：四年正收益，是最扎实的部分。

### 8.2 已知风险

1. **成本假设**：全模型按 0.1%/边。若实际滑点到 0.15%/边，V6 净收益归零；
2. **容量**：持仓集中在池内最小 20% 市值段，单票日均成交额有限（V4 有 5000 万下限）；
3. **风格依赖**：整条线本质是"小盘 + 冷门 + 反转"溢价，2024 年那种行情是主要收益来源；
4. **样本外太短**：决策器只在 81 个样本外交易日触发过。

### 8.3 上线前检查清单

- [ ] 纸面跟踪 ≥ 3 个月，对比 `wpqc_v6_signal.csv` 与实际成交
- [ ] 用实际佣金/滑点重算净收益
- [ ] 检查持仓的日均成交额是否覆盖下单量
- [ ] 参数冻结：窗口 120、阈值 0.5、IQR5 定义不再变动
- [ ] 准备好"决策器失效"的退出条件（例如连续 6 个月跑输纯 V3）
