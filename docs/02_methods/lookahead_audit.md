# 前视体检（Lookahead Audit）

> 门 6 的第一项，也是**最便宜、最容易改变结论**的一项。
> 代码：`factorlab.audit.lookahead`
> 配套：`docs/01_architecture/pit_policy.md`（铁律）、`registry/field_pit.yaml`（字段表）

---

## 0. 一句话

**前视不是"运气差"，是"偏差"。** 运气会随样本变长而收敛，偏差不会。

旧项目花了 3 年、经过完整审计，最后找到的**唯一一个可证伪偏差**就是它：

```
amt20 = 含当日 15:00 成交额的 20 日均额
决策在 14:45
→ 净年化虚高 1.66pp，6.02% 的选股改变
```

而这**只用了 15 分钟的提前量**。

## 1. 四道检查（自动跑）

```bash
python -m factorlab.audit.lookahead \
  --panel  data/panels/panel_..._v3.parquet \
  --fields registry/field_pit.yaml \
  --out    artifacts/results/<run_id>/lookahead
```

产出 `lookahead_report.txt` + `lookahead_detail.csv`。

### 检查 A · 字段覆盖（有没有来路不明的列？）

```
panel 的每一列 → 能否在 field_pit.yaml 找到定义？
```

任何"查不到出处的列"直接判失败。理由很实际：
**你三个月后不会记得 `foo_ratio` 是什么**，而它正在决定选股。

### 检查 B · shift 复算

对标记 `needs_shift: true` 的字段，用 curated 原始数据重算两版：

```
v_with_today  = rolling(20).mean()
v_lag1        = rolling(20).mean().shift(1)
```

然后检查 panel 里存的是哪一版（逐值比对，允许浮点误差 1e-10）。

不一致 → 报错，并给出：
- 影响的 (date, ticker) 行数
- 受影响的选股比例
- 修正前后的净年化差

### 检查 C · 截断不变性（最有说服力）

> **只用 `<= as_of(T)` 的数据重算 T 日决策，结果必须与用全量数据算出的完全一致。**

```python
# 全量数据算出的 T 日选股
picks_full = run_pipeline(data_until_end, date=T)

# 把 T+1 之后的数据全部删掉，重算
picks_trunc = run_pipeline(data_until_asof(T), date=T)

assert picks_full == picks_trunc      # 必须逐只相等
```

这条检验的哲学是：**如果结果依赖"未来才存在的数据"，那么删掉未来，结果必然变化。**

旧项目 `cls_pool/verify_pit.py` 用这个方法做 8/8 通过，称它为"PIT 的决定性检验"。
值得照抄。

**建议抽样日**：至少包括
- 一个长假后的交易日（信息堆积最多）
- 一个市场极端日（涨跌停最多，最容易暴露）
- 数据起点的第 121 天（预热期刚结束）
- 随机 5 天

### 检查 D · 口径差异量化

把"修正前 / 修正后"并排列出来：

| 口径 | 净年化 | Sharpe | 选股变化率 |
|---|---|---|---|
| 修正前（含前视） | | | — |
| 修正后（shift 1） | | | |

**判定线：**

| 跌幅 | 判定 |
|---|---|
| **< 0.5pp** | ✅ 通过（前视影响可忽略，但仍要修） |
| 0.5 ~ 1.0pp | ⚠️ 需单独解释 |
| **> 1.0pp** | ❌ 不通过，说明"尾盘放量股"在贡献收益，必须查清 |

## 2. 手工检查清单（自动化做不了的）

自动化只能查"表里登记过的字段"。以下五类必须人看：

### 2.1 股票池 / 成分股

```python
# ❌ 幸存者偏差
codes = rqdatac.index_components('000300.XSHG')          # 今天的成分

# ✅ 逐日
codes = rqdatac.index_components('000300.XSHG', date=d)
```

**还要检查**：ST 标记、退市、上市未满 N 日、板块变更——这些状态必须用**当时**的值。

### 2.2 财务 / 基本面数据

财务数据的 PIT 极其复杂（报告期 ≠ 公告日）。必须用**公告日**而非报告期：

```
❌ f = pe_ratio(report_date='2024-12-31')  → 在 2024-12-31 用？错
✅ f = pe_ratio(announce_date<=as_of)      → 用当时已公告的最新报告
```

**规则**：任何基本面字段，`field_pit.yaml` 里必须写 `availability: announce_date`。

### 2.3 复权因子

```
❌ 用当前的复权因子重算历史价格
✅ 用 as_of 时点已知的复权信息
```

后复权的序列在**每次分红送股后都会整体变化**。用后复权做回测是惯例（收益率正确），
但要注意：**"当时的绝对价格"不可得**，因此任何依赖绝对价格的判断（如"股价 < 5 元"）都不能用后复权价。

### 2.4 分组 / 排序的并列处理

```python
rank(method='first')   # 并列时按出现顺序，结果依赖行序
rank(method='dense')   # 并列同名次
```

旧项目离线复现与生产差 0.17pp，原因就是 `rank(method='first')` 的并列处理不同。
**并列处理必须固定并写进代码，不能依赖 pandas 默认。**

### 2.5 时间对齐

| 陷阱 | 例 |
|---|---|
| 时区 | RQData 返回 UTC，本地假设 Asia/Shanghai → 差 8 小时，跨日 |
| 交易所在不同时区 | A 股 + 美股混排 |
| 夏令时 | 美股相关 |
| `shift` 的单位 | 行数 vs 天数。有停牌日的股票，`shift(1)` 是"上一行"不是"昨天" |

**规则**：`shift` 的语义必须在代码里注释清楚是"行位移"还是"日历位移"。
停牌日保留在索引里（值为 NaN）能让两者一致——这也是 `data_layer.md` 要求"停牌日保留在索引里"的原因。

## 4. 常见前视模式速查

| 模式 | 典型代码 | 修法 |
|---|---|---|
| 当日累计量 | `volume.sum()` 当日 | 构造 `v_upto_asof` |
| 含今日的滚动 | `rolling(20).mean()` | `.shift(1)` 加在 rolling 之后 |
| 最新成分股 | `index_components()` | 逐日取 |
| 最新市值 | `mktcap.iloc[-1]` | 逐日取 |
| 报告期当公告日 | `pe(report_date=d)` | `pe(announce_date<=d)` |
| 未来收益泄漏 | `ret.shift(-1)` 混入因子 | 因子与标签必须物理隔离（不同文件） |
| 全样本标准化 | `(x - x.mean()) / x.std()` | 逐日截面标准化 |
| 全样本分位 | `x.rank(pct=True)` 用全历史 | `x.expanding(120).apply(...)` 或用当日截面 |
| 索引错位 | `bars.shift(1)` 跨日 | 用 `groupby(ticker).shift(1)` |
| 时区 | UTC 当本地 | `tz_localize('Asia/Shanghai')` 后 `tz_convert` |

## 5. 频率与时机

| 时机 | 做哪几项 |
|---|---|
| **新增字段** | 检查 A（登记 PIT）+ 人工检查 2.1~2.5 |
| **新增因子** | 检查 A + 检查 C（截断不变性，抽样 8 天） |
| **每次正式回测前** | A + B + C + D 全跑 |
| **写进 `docs/03_knowledge/` 之前** | 全跑 + 报告归档 |

**成本**：检查 A/B/D 是分钟级。检查 C 取决于 pipeline 重算成本——
若 pipelin 可离线复现（如旧项目的 `overfit_lab/core.py`），C 也是分钟级。

> **所以优先把 pipeline 做成"可以不连行情库、用本地快照复现"的结构**
> （旧项目 `overfit_lab` 的核心设计目标）。否则截断不变性检验会贵到没人做。

## 6. 与 PIT 表的关系

```
registry/field_pit.yaml   ← 声明（人写）
        ↓
factorlab.audit.lookahead ← 验证（机读）
        ↓
docs/03_knowledge/*.md    ← 引用（结论里注明"已通过 PIT 审计"）
```

**PIT 表是唯一真相源。** 如果代码与表不一致，**以表为准**，改代码。
因为表是被人 review 过的，代码不是。
