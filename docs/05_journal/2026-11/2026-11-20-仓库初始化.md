**最值钱的东西**：`wpqc/EXPERIMENTS_V1_V6.md`（30 KB）、`P0_P1_RESULTS.md`（17 KB）、

**最危险的东西**：数据的组织方式。
`wpqc/` 根目录下有 `LDmac_01.csv`、`LDmac_cpv_016.csv`、`wpqc_v6.csv`、
`panel_*.pkl`（461 MB）、`min_merged_raw_data.csv`（1.9 GB）……
**没有层级，所以无法判断一个文件的角色**。这是"18 个月后没人说得清哪个 CSV 是哪次跑的"的直接原因。

## 和我预期不一样的地方

- **预期**：旧项目最大的问题是过拟合。
- **实际**：过拟合已经被管住了（证伪清单很长，安慰剂做了，PBO 算了）。
  真正的问题是**三层错位**：
  1. **数据层没有分级** → 无法判断可重建性 → 不敢删 → 越积越乱
  2. **审计层缺失** → 有 IC 证据，没有 DSR / PBO / 禁运 / PI
  3. **知识没有出口** → 结论散落在 5 个 md 和 20 个 CSV 里，无法被下一个项目继承

- **预期**：应该把旧代码合并进来。
- **实际**：应该**只合并知识，不合并代码**。
  旧代码有约 40% 的重复（`strategy01~08.py`），合并进来只会把混乱一起搬过来。
  正确的做法是**重写薄薄一层可复用的库**（`src/factorlab/`），变体用 config 表达。

## 决定

- [x] **继续**：按五层结构建仓库，知识优先、数据分级、状态机管理因子生命周期
- [x] 旧文档**逐字复制**进 `docs/04_legacy/`（不改不删，可 diff 核对）
- [x] 旧代码**不复制**，只记录"值得搬什么"（在各 legacy 目录的 README 里）
- [x] 数据命名**沿用旧项目**（`cn_stock_30m_post_close_20200101_...parquet`），
      这样旧缓存可以直接软链复用，不需要转换
- [x] 把 `trials_log.csv` 设为**一等公民**，并在初始化时就补上旧项目 N≈110 的历史账

**明确不做**：

- 不做统一的自动回测框架（每个研究方向可以有自己的 `run.py`）
- 不做数据库（YAML/CSV 够用，且要能 git diff）
- 不把旧项目的 notebook 搬进来（22 MB 的 `test01.ipynb` 不是文档）

> ⚠️ 一个诚实的说明：**旧项目的历史 N 只是"可清点"的下界。**

> 因此 `σ(SR)` 仍然算不出来，DSR 仍只能给区间。

## 遗留问题

1. **真市值表还没有接入**。`cn_stock_market_cap_*.parquet` 在旧项目里存在，
   但从未参与正交化 —— 补上之后 `amihud` 的独立性结论可能变化（预期会更差）。
2. **`vol_ratio` 的 bar 选择没做敏感性**（14:00 vs 14:30 vs 累计量）。
   这是三因子里唯一独立的那个，值得单独一轮。
3. **`tier` 的窗口敏感性没做**（102 / 72 根 bar 是唯一没留对照数字的参数）。
   旧项目标准是符号一致率 > 85%。
4. **`coef_std` 的消融测试从未做**。IC ≈ 0 却还在 V1 打分里决定 3 只票。
5. **执行价假设**（中点近似）没有做过敏感性。这是 `ret_total` 的系统性偏差来源。
6. **离线复现层**（对应旧项目 `overfit_lab/`）尚未实现。
   没有它，截断不变性检验和置换重要性都会贵到没人做。

## 附：本次设计的四条依据

| 设计选择 | 依据 |
|---|---|
| 文档分 `01_architecture` / `02_methods` / `03_knowledge` / `04_legacy` / `05_journal` / `06_adr` | 旧项目 wpqc 的四层文档体系（对外 / 对内 / 实验 / 测试设计）已被证明有效，只是缺"为什么这样设计"和"过程日志"两层 |
| 数据分 raw / curated / features / labels / panels | 旧项目"一个 data 目录 + 混合命名"是最大痛点；五级让每级的可重建性明确 |
| `registry/` 用 YAML/CSV | 需要人读、需要 git diff、需要写进报告。数据库不满足这三条 |
| 强制 `field_pit.yaml` + 截断不变性检验 | 旧项目唯一的"可证伪偏差"就是 amt20 的 15 分钟前视，值 1.66pp。PIT 必须是制度，不能靠自觉 |

## 附二：初始化当天的自检结果

| 项 | 结果 |
|---|---|
| `pytest tests -q` | **60 passed**（门 4 正交化 5 项 / 门 6 禁运 4 项 / 数据层面板 10 项 / 技能契约 10 项） |
| `python -m factorlab.audit.registry_check` | **通过**（14 因子，状态分布正常；active 都有退役条件） |
| `python -m factorlab.audit.lookahead --registry-only` | **PASS** |
| 试验记账 | 24 行，可清点 **N = 941**；σ(SR) = **0.247** |
| 文档 | 主 README + 6 个 docs 分区 + 25 份 legacy 原文 + 5 份 legacy 索引 |

**一个有趣的巧合**：算出来的 σ(SR) = 0.247，正好落在旧项目 DSR 敏感性网格的中间档（0.25）。
这意味着**如果旧项目当时就记账，DSR 的答案大概率就是那张表中间那一列（0.54）** ——
而不是"0.51~0.77 之间不知道"。

这正是"记账"的全部意义：把一个区间变成一个数。
