## 这三个文件的严格分工

```
lessons_learned.md   我们犯过什么错，为什么错，以后怎么做    ← 面向"人"
factor_zoo.md        哪些因子被测过，结果如何，现在什么状态  ← 面向"因子"
falsified.md         哪些方向别再试，死因是什么              ← 面向"时间"
```

**同一个事实上可能出现在两处**（例如 MAX 因子与波动率相关 0.874）：
- `factor_zoo` 里写它的**当前状态**
- `lessons_learned` 里写它作为**教训**的普适含义
- `falsified` 里写"**别再试**"

三处都要有，但**只有一处是主叙述**，其余链接过去。主叙述的位置：

| 内容类型 | 主叙述在 |
|---|---|
| 某个因子的具体数字 | `factor_zoo.md` |
| 某个方向的"别再试" | `falsified.md` |
| 跨因子的方法论教训 | `lessons_learned.md` |

## 进入本目录的门槛

**一条结论要写进这里，必须：**

- [ ] 走完 [`../02_methods/research_workflow.md`](../02_methods/research_workflow.md) 的 7 道门
- [ ] 每个数字都能由仓库内代码 + `data/MANIFEST.csv` 记录的数据重算
- [ ] 写清**口径**（区间 / 池 / 成本 / 标签）
- [ ] 写清**证据出处**（哪个 `run_id` / 哪个文件 / 哪张表）
- [ ] 如果是负面结论，写清**死因**（不是"效果不好"，是"因为 X"）

**不满足以上任一条**：它在 `05_journal/` 或 `research/<dir>/conclusion.md` 里，
不在 `03_knowledge/` 里。

## 维护规则

| 规则 | 理由 |
|---|---|
| **只增不改** | 原错误本身是教训。发现错了 → 加一条"更正" |
| **每条必须有数字** | 没有数字的"经验"是意见，不是知识 |
| **每条必须写落地** | 不落地的教训会重复发生 |
| **引用其他文件用相对路径** | 移动目录时不失效 |

## 一个判断：这份文件在变好吗

三个信号：

1. **`falsified.md` 在变长** —— 说明真的在探索（而不是在已知有效的地方打转）
2. **`lessons_learned.md` 的新增条目在变少** —— 说明旧教训真的被吸收了
3. **`factor_zoo.md` 里 `active` 的比例在下降** —— 说明标准在收紧，这是好事

**警惕**：如果 `active` 越来越多、`falsified` 几乎不增长，
那不是在进步，是在降低标准。
