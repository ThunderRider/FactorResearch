# 命名与口径约定

> 本文件的目的只有一个：**让同一个人隔六个月回来看，不需要重新推断任何含义。**
> 口径不一致是量化研究里最贵的 bug —— 它不报错，只是让你的数字和别人的数字没法比较。

---

## 1. 时间

| 项 | 约定 | 反例 |
|---|---|---|
| 日期字符串 | `YYYY-MM-DD`（ISO 8601） | `2026/11/20`、`11-20-2026` |
| CSV 内的交易日期 | 优先 ISO；若必须 `YYYYMMDD`（与旧项目对齐），列名必须是 `TRADE_DT` 且为**字符串** | 存成整数 `20261120`（丢前导零、Excel 会转日期） |
| 时间戳 | 带时区，`2026-11-20T16:40:00+08:00` | 裸 `16:40:00` |
| 分钟 bar 时间 | **bar 的结束时刻**。`14:30:00` = 14:00–14:30 | 用开始时刻（与旧项目不一致） |
| 交易日 vs 自然日 | 一律交易日记账；自然日只在必须时显式标注 | 用 `pd.date_range` 直接生成日期轴 |
| Excel 序列号 | ❌ 永不使用 | 旧项目 `EXPERIMENTS §5.8` 的教训 |

> **为什么 "bar 结束时刻" 要写进约定**：旧项目做过一次 Excel 自然日斜率复核，
> 小盘池的信号符号翻转了 **23%**，净收益从 +9.55% 变成 −1.37%。
> 时间轴口径错了，结论会反。

---

## 2. 收益与标签

| 项 | 约定 |
|---|---|
| 收益的**存储形式** | **小数**：`0.0123` = +1.23%。不用百分数（`1.23`） |
| 报告里的**展示形式** | 百分数，保留两位：`+1.23%` |
| 年化 | `(1 + 日收益).prod() ** (252 / n) - 1`，`252` 来自 `configs/default.yaml` |
| 夏普 | `年化收益 / (日收益标准差 × √252)` |
| 最大回撤 | `min(nav / nav.cummax() - 1)`，负数 |
| 超额收益 | 组合收益 − **同敞口**基准收益。敞口不同时必须先折算 |
| 多空/分组收益 | 一律报**日均 bp**（`1bp = 0.01%`），并同时给中位数 |

**标签命名**（与 `registry/labels.yaml` 一致）：

```
ret_<入场时点>_<出场时点>[_dN]

ret_1445_next_1115     T 日 14:45 买入（用 (c1430+c1500)/2 近似），T+1 日 11:15 卖出
ret_1445_next_1330     T 日 14:45 买入，T+1 日 13:30 卖出
ret_overnight          T 日 15:00 → T+1 日 9:30
ret_morning            T+1 日 9:30 → T+1 日 11:15
ret_tail               T 日 14:45 → T 日 15:00
ret_1d / ret_5d / ret_20d   持有 1 / 5 / 20 个交易日（次日开盘买入）
```

**三段分解是强制的**：`ret_total` 必须能被拆成 `ret_tail × ret_overnight × ret_morning`
（乘法，乘积严格等于总收益）。理由：因子对"隔夜"和"早盘"的预测力完全不同——
如果某个因子只在隔夜段有 IC，说明它赚的是隔夜溢价，改进方向就该是尾盘资金意图，
而不是继续调窗口。

## 3. 时点近似

回测口径无法精确到分钟时，用**相邻 bar 的中点**近似，并**在报告里写明**：

```
入场（≈14:45） = (c1430 + c1500) / 2
出场（≈11:15） = (次日 c1100 + 次日 c1130) / 2
出场（13:30）  = 次日 c1330
```

**近似必须标注**。旧项目的 `STRATEGY_V6_FINAL.md` 附录 A 专门写了这段，
这是"诚实"与"选择性展示"的分界线。

## 4. 成本

| 项 | 约定 |
|---|---|
| 默认单边成本 | `0.10%`（佣金 + 印花税 + 滑点合计），见 `configs/default.yaml` |
| 敏感性 | 必报三档：`0.10% / 0.15% / 0.20%` |
| 日频全换手的每日成本 | `单边 × (今日敞口 + 昨日敞口)` |
| **盈亏平衡线** | 每单位敞口日收益 > **0.200%** |

> **为什么盈亏平衡线是本仓库的固定指标**：评价这类策略，看"年化收益"没用，
> 要看"每单位敞口的日收益"——它把"选股质量"和"仓位大小"分开了。
> 仓位大小只改变成本，选股质量决定能不能跨过成本线。
> 旧项目 V1 每单位敞口日收益 0.196%，只差 0.4bp，结果净 −0.9%；V3 是 0.315%，净 +9.4%。

## 5. 单位

| 量 | 单位 | 注意 |
|---|---|---|
| 价格 | 元 | 后复权序列的绝对值无经济意义（不是真实股价），只用于算收益 |
| 成交额 | 元 | RQData `total_turnover` 单位是元 |
| 成交量 | 股 | 不是手（1 手 = 100 股） |
| 市值 | 元 | 报告里用亿元 |
| 因子值 | 无量纲（z-score / 比值 / 百分比） | 归档时必须写清是哪种 |
| 相关系数 | Pearson / Spearman **必须标注** | 因子间默认 Spearman（RankIC） |

## 6. 代码命名

```python
# 变量
df / panel / wide / long / agg          # 数据类型后缀
g_*        # groupby 对象          g_date = df.groupby('date')
z_*        # 标准化后的值          z_vol
n_*        # 计数                  n_miss
is_*, has_*# 布尔                  is_tradable
_*         # 临时/内部

# 函数
动词_名词：compute_vol_ratio / load_panel / build_snapshot
布尔用 is_ / has_：is_tradable / has_volume
不缩写：amt20 而不是 a20（成交额），turnover 而不是 to

# 常量
UPPER_SNAKE：AMT_WINDOW / Z_CLIP / COST
```

**列名**：

| 类型 | 规范 | 例 |
|---|---|---|
| 因子 | `snake_case`，与 `registry/factors.yaml` 的 `id` **完全一致** | `vol_ratio` |
| bar 派生的快照字段 | `<字段首字母><HHMM>` | `c1430`（14:30 收盘）、`v1430`（14:00–14:30 量） |
| 标签 | `ret_*` | `ret_total` |
| 元信息 | `pool` / `date` / `ticker` / `tradable` | |

> `c1430` 这种命名看起来不友好，但它是**旧项目 3 年里最省事的约定**：
> 一眼看出是哪个时点、哪个字段，`grep c1430` 能横跨所有文件命中。
> 沿用，不要"优化"。

## 8. 数字的写法

写完任何一张表，自查：

- [ ] 每个数字都带单位（`%` / `bp` / `元` / 无量纲）
- [ ] 每个数字都带**口径**（哪个区间、哪个池、哪个成本）
- [ ] 对比表的行和列是**同口径**的（不同口径的数字不许放在同一列比较）
- [ ] 显著性同时给 `t` 与 **有效样本数**（重叠窗口下 naive t 会高估 30%+）
- [ ] 点估计旁边有**区间**（块自举 95% CI）
- [ ] 保留位数统一：收益 2 位小数（%），IC 4 位，t 值 1–2 位

> 反面教材（真实出现过）：`STRATEGY_V6_FINAL.md` 写"滚动 12 个月从未为负（最差 +8.01%）"，
> 但那是 **13:30 出场 + 决策器**的口径；审计用 11:15 口径的 V3 重算，
> 有 **12.7%** 的滚动窗口为负，最差 **−2.93%**。
> 数字没错，**口径没写在同一个句子里**，就成了选择性展示。

---

## 9. 禁止事项

| ❌ | 原因 |
|---|---|
| 用自然日当交易轴 | 符号翻转的经典来源 |
| 用最新成分股回测历史 | 幸存者偏差 |
| 把 percent 和 decimal 混用 | 差 100 倍，且不报错 |
| 在 CSV 里存 Excel 日期序列号 | 无法跨工具解读 |
| 用 `0` 表示缺失 | 与"真的是 0"无法区分；用 `NaN` |
| 前向填充后当作"原始数据" | 掩盖了缺失，且引入未来信息 |
| 报告里只给最优口径 | 必须同时给主口径与成本敏感性 |
