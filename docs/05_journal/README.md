# 05 · 研究日志（Journal）

> **这里按日期记录"某天我们做了什么、看到了什么、决定不做什么"。**
> 与 `03_knowledge/`（提炼后的结论）和 `04_legacy/`（旧项目档案）不同，
> 这里是**过程**，不是结论。

---

## 唯一的规则：只追加，不改历史

```
❌ 回头把 2026-11-20 的日志改成"其实我们当时想到了"
✅ 2026-11-25 加一篇：「对 2026-11-20 的更正：……」

```

**为什么**：日志的价值在于它记录了**当时**的认知状态。
如果你能改写历史，你就无法判断"这个想法是新发现的，还是事后合理化"。

---

## 目录结构

```
05_journal/
├── README.md              ← 你在这里
├── _TEMPLATE.md           模板
├── 2026-11/
│   ├── 2026-11-20-仓库初始化.md
│   └── ...
└── 2026-12/
    └── ...
```

**按月分目录**，文件名 `YYYY-MM-DD-<slug>.md`。
一天可以有多篇（不同主题各一篇）。

---

## 什么时候写

| 时机 | 写什么 |
|---|---|
| 开了新研究方向 | 假设、为什么现在做、预期 |
| 放弃一条路 | **为什么放弃**（这条最重要） |
| 发现异常数据 | 现象、怎么发现的、初步判断 |
| 某个结果和预期相反 | 差异在哪、可能的原因 |
| 状态变更（factor active → retired） | 触发条件、证据 |
| 每月末 | 本月产出 / 消耗 / 下月计划 |

**只有一种情况不用写**：纯粹的工程性改动（重命名、重构、修 bug），
那属于 commit message。

---

## 与其它目录的关系

```
        journal（过程）              knowledge（结论）
   2026-11-20 试了 X，失败           X 已证伪（见 falsified.md L3）
        │                                  ▲
        └──────── 提炼 ────────────────────┘
```

**一篇日志可以什么结论都没有。** 这很正常 ——
日志记录"试过"，知识记录"学到"。

---

## 每月回顾模板

月末花 15 分钟填这个，比写十篇日志都有用：

```markdown
## 2026-11 回顾

**产出**
- 新增研究：__ 个（__ 个到 candidate，__ 个 rejected）
- 状态变更：__ 个
- 新增试验：N += __（累计 __）
- 新增知识条目：__ 条

**消耗**
- 哪条路花的时间最多但没产出：__
- 哪个假设被推翻：__

**下月**
- 优先级 1：__
- 优先级 2：__
- 明确不做：__

**一个反思**
__
```

---

## 反模式

| ❌ | 为什么不行 |
|---|---|
| 写"今天研究了一下因子" | 没有信息量。要写"试了 X，IC 是 Y，判定 Z" |
| 只记成功的 | 失败的记录价值更高（避免重复） |
| 用日志代替结论 | 日志不提炼，三个月后自己都看不懂 |
| 事后补写并声称是当时的想法 | 破坏日志的唯一价值 |
