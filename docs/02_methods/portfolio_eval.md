# 组合层评估：从"因子有信号"到"策略能赚钱"

> 门 5 的展开。**核心问题：这个信号在真实成本、真实换手、真实容量下，还剩多少？**
> 代码：`factorlab.portfolio.*`

---

## 1. 第一原则：别看年化收益

```
年化收益 = 选股质量 × 仓位大小 − 成本 × 换手
```

三个东西混在一个数里。要判断策略好坏，必须把它们拆开。

**拆开的方法**：

```
每单位敞口的日收益 = Σ(权重 × 收益) / Σ(权重) / 天数
每日成本率        = 单边成本 × (今日敞口 + 昨日敞口)
盈亏平衡线        = 0.200% / 日（= 0.1% × 2）
```

> **旧项目的对照**（同一年化收益，不同含义）：
>
> | 方案 | 每单位敞口日收益 | 对 0.200% 盈亏线 | 净年化 |
> |---|---|---|---|
> | V1 | 0.196% | **差一点** | −0.9% |
> | V2 | 0.217% | 刚过线 | 0.0% |
> | V3 | 0.315% | 过线 | +9.4% |
> | V6 | 0.315%（选股同 V3） | 过线 | +13.7% |
>
> V1 只差 0.4bp，结果净收益是负的。**报告"V1 毛年化 21.5%"会让人以为它很赚钱。**

**必报格式**：

```markdown
| 方案 | 每单位敞口日收益 | 日均敞口 | 毛年化 | 日成本 | 净年化 | Sharpe | MDD |
```

## 2. 五个必须报的数

### 2.1 每单位敞口的日收益（最重要的单一指标）

```python
per_unit = (weights * returns).sum(axis=1) / weights.sum(axis=1)
daily_per_unit = per_unit.mean()
```

**判定线**：`> 0.200% + 0.05pp 安全垫`。低于这条线，任何仓位调整都救不回来。

### 2.2 最大回撤 + **恢复时间**

```python
mdd = (nav / nav.cummax() - 1).min()
recovery_days = days_from_trough_to_new_high
```

**恢复时间比回撤幅度更重要**：
回撤 −20% 但 2 个月恢复，和回撤 −20% 但 10 个月恢复，是完全不同的产品。

> 旧项目 V6：MDD −24.93%，回撤期间 2023-11-03 ~ 2024-02-06，**恢复 288 天**。
> 那段时间正是 2024 年初的小盘股流动性危机（全市场小盘两周跌 30%+）。
> 这说明回撤的原因不是"策略失效"，而是"策略所在的环境崩了"——但**产品层面一样要承受**。

### 2.3 收益集中度

```python
top10_contribution = daily_gross.nlargest(10).sum() / daily_gross.sum()
```

**判定线**：`< 50%` 算健康。

> 旧项目 V1：**97%**（意味着其余所有日子合计是负的）。
> V6：**53%**。这是"尾盘 + 次日"这类超短周期策略的**固有特征**，不是缺陷——
> 但它意味着"单月业绩会很不均匀，评价至少要放在 12 个月的窗口里"。

### 2.4 换手率与名称重合度

```python
turnover = 1 - len(today ∩ yesterday) / len(yesterday)
```

| 量 | 用途 |
|---|---|
| 名称换手率 | 执行难度、成本、容量 |
| 资金换手率 | 与成本直接挂钩 |
| 相邻日持仓重合 | 判断"是不是每天在重新洗牌" |

旧项目 V3：相邻两日持仓重合 **44.0%**（日换手 56%），日频全换手的极端情形。

### 2.5 成本敏感性（三档）

```python
for c in [0.0010, 0.0015, 0.0020]:
    net = backtest(..., one_way=c)
```

**必报**，且必须说明"哪一档归零"。

> 旧项目：成本每增加 5bp/边，年化下降约 **8.3pp**。
> `13:30 出场` 带来的 +4.3pp 增量，被"卖出腿多付 5bp"完全抵消——
> **它没有安全边际**。这是"待验证"而非"已证实"的核心原因。

## 3. 脆弱性曲线（Fragility）

### 3.1 做法

剔除最好的 k 个交易日后重算净年化，k ∈ `[0,1,2,3,5,8,10,20]`：

```python
from factorlab.eval.stability import fragility_curve
frag = fragility_curve(daily_net, ks=[0,1,2,3,5,8,10,20])
```

### 3.2 判读

| 形态 | 含义 |
|---|---|
| k=5 仍 > 0 | 稳健，收益不过度依赖极端日 |
| k=5 归零 | **结构性脆弱**，必须披露 |
| k=1 就归零 | 一个交易日撑起全部，风险极高 |

> 旧项目 V3：k=0 → 9.44%，k=5 → **−0.02%**。
> 反向（剔除最差 10 天）：+23.15%，Sharpe 1.71。
> **盈亏对称地依赖极端日**——这不是"净值平滑"型的骗局，而是"少数日撑起全部"型的。

### 3.3 为什么每次回测都要生成

旧项目的自我批评："只有'前 10 天贡献 53%'定性，无曲线"。
把曲线固化成 `fragility.csv`，每次回测自动重算 —— 让"脆弱"变成**默认暴露的东西**，
而不是"被问到才说"。

## 4. 块自举：给点估计配一个区间

```python
from factorlab.eval.stability import block_bootstrap_metrics
ci = block_bootstrap_metrics(daily_net, block=20, n=3000)
# → {'ann': (lo, hi), 'sharpe': (lo, hi), 'p_ann_negative': 0.148}
```

**块长** ≈ 最大重叠窗（20 个交易日），因为日收益也有惯性。

> 旧项目 V3：年化 95% CI = **[−7.3%, +28.9%]**，P(年化<0) = **14.8%**。
> **在 3.2 年、单一路径的数据预算下，+9.4% 与 0 在统计上还没被分开。**

这句话必须写进材料。否则"年化 13.69%"会被当成点估计，而它其实是一个宽区间的中部。

**样本长度与可分辨性的粗略关系**（日频、Sharpe≈0.7、日波动 1.5%）：

| 年数 | 年化 95% CI 宽度（约） | 能否区分 "+10%" 与 "0" |
|---|---|---|
| 1 | ±25pp | ❌ |
| 3 | ±15pp | ⚠️ 勉强 |
| 5 | ±11pp | ✅ |
| 10 | ±8pp | ✅✅ |

**结论：3 年数据做不出"策略有效"的结论，只能做出"值得继续观察"。**

## 5. 分年 / 分 regime

```python
by_year = daily_net.groupby(daily_net.index.year).apply(perf)
```

**必报**。判定：

```
至少 3/4 年为正；最差年份 > -10%；无单年贡献 > 60% 的累计收益
```

> 旧项目 V6（13:30 口径）分年：2023 +3.73% / 2024 +31.47% / 2025 +20.75% / 2026 +4.33%。
> 四年全正 ✅，但 2026 明显衰减（+4.33% vs 2024 +31.47%）→ 标注"风格依赖强"。
>
> 反面案例：行业动量前 30% 全样本 27.1%，但 **2024 一年贡献 20.3%**，样本外 −11.9%。
> 如果只看全样本，会得到完全错误的结论。

## 6. 超额收益：alpha 还是 beta？

### 6.1 必须做基准对照

```python
excess = portfolio_ret - benchmark_ret * exposure
t = mean(excess) / std(excess) * sqrt(n)
```

**关键：基准要按组合的实际敞口折算。**

> 旧项目：基准 = 中证500 + 中证2000 各 50%，按组合当日敞口折算。
> 结果：对基准 beta 仅 **0.43–0.45**，年化超额 25.85%，超额 t = **3.40**。
> 这说明收益大头来自选股，不是市场方向。

### 6.2 增量窗口的单独检验

改一个执行细节（如延后卖出）带来的收益，必须单独验证是 alpha 还是 beta：

| 窗口 | 策略 | 指数 | 超额 | t |
|---|---|---|---|---|
| 14:45 → 次日 11:15 | +23.37bp | +4.47bp | +18.90bp | 4.03 |
| **11:15 → 13:30（增量）** | **+2.59bp** | **−0.29bp** | **+2.88bp** | 1.65 |

**读懂这张表**：增量窗口里**指数是跌的**（−0.29bp），**策略是涨的**（+2.59bp）。
如果延后卖出只是"多承担市场风险"，这段应该跟着指数一起跌。实际相反 →
赚的是**个股层面的 alpha**，不是 beta。

**但 t=1.65 只是边际显著**，且 5bp 滑点即归零 → 判"待验证"而非"已证实"。

## 7. 容量：从"能赚"到"能装多少钱"

### 7.1 参与率法

```
单票下单额 = AUM × 单票权重
参与率     = 单票下单额 / 该时段成交额
```

**目标参与率 ≤ 5%（保守）/ 10%（可接受）**。

> 旧项目：按 5% 参与率、单点出货，**AUM 上限约 600 万**（33% 敞口）。
> 要支撑 1000 万以上，必须把卖出拆成 3–4 批（13:00–14:30）。

### 7.2 平方根冲击模型

```
impact = Y × σ_daily × √(参与率)          常用 Y = 0.5
```

**必做**：把冲击成本写成参与率的函数，重算 AUM 1000万/3000万/5000万 三档的净收益。

> 旧项目用 σ=2.8%、Y=0.5：AUM 1000 万、单票权重 16.8% 时冲击约 68bp。
> 这个数字比固定 0.1% 成本高一个数量级 —— **说明实际容量比固定成本假设下小得多。**

### 7.3 报告格式

```markdown
| AUM | 单票权重 | 单票下单额 | 参与率 | 冲击成本 | 净年化 |
|---|---|---|---|---|---|
| 600 万 | | | | | |
| 1200 万 | | | | | |
| 2400 万 | | | | | |
```

## 8. 执行假设：中点近似不是可成交价

旧项目的入场价是 `(c1430 + c1500) / 2`，出场是 `(c1100 + c1130) / 2`。
这是**中点近似**，不是真实可成交价。

**必须做的敏感性**：

| 假设 | 说明 |
|---|---|
| 中点近似（基准） | 当前口径 |
| 决策后第一根 bar 的**开盘** | 更接近真实成交 |
| 该时段的 **VWAP** | 拆分大单时的真实均价 |
| **加 1 根 bar 延迟** | 最保守 |

**判定线**：入场假设变化导致下修 **< 1pp**。

## 10. 错误清单

- [ ] 只报年化收益，不报"每单位敞口日收益"
- [ ] 不报最大回撤的**恢复时间**
- [ ] 不报收益集中度
- [ ] 不报成本敏感性
- [ ] 不生成脆弱性曲线
- [ ] 只给点估计，不给块自举区间
- [ ] 不报分年（掩盖了"单年驱动"）
- [ ] 超额不对基准折算敞口（虚高）
- [ ] 用中点近似当成交价却不做敏感性
- [ ] 用固定成本代替冲击模型（容量虚高）
