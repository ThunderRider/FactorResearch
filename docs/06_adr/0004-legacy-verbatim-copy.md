# 0004 · 旧文档逐字复制，不重写

- **状态**：已接受
- **日期**：2026-11-20
- **关联**：[`../04_legacy/README.md`](../04_legacy/README.md)

## 背景

旧项目有 25 份文档（合计约 200 KB），其中 3 份是核心资产：

- `EXPERIMENTS_V1_V6.md`（30 KB）：V1→V6 全部实验与对照数字
- `P0_P1_RESULTS.md`（17 KB）：12 项防过拟合检查的判定与结果
- `OVERFITTING_TESTS_V6.md`（28 KB）：测试设计依据 + 该做但没做的清单

新仓库要继承它们。怎么继承？

## 选项

**A. 重写成新文档**（提炼 + 更新口径）

- 优点：干净、口径统一、可读性最好
- 缺点：**会丢信息**。原文里那些"对照数字"（例如"剔除最好 5 天，k=0→9.44%、k=1→6.29%、
  k=3→3.01%、k=5→−0.02%…"）在重写时很容易被压缩成一个结论，而**那些数字本身就是证据**；
  而且重写会不可避免地带入"事后认知"，让历史变成"其实我们当时就想到了"

**B. 只保留链接**（文档留在旧目录）

- 优点：零成本
- 缺点：旧目录会继续腐烂（`my_quantproject` 不是长期仓库）；且跨目录引用很脆弱

**C. 逐字复制 + 写来源索引**（本决定）

- 优点：零信息损失；可 `diff` 核对；原文的"错误"也被保留（错误本身是教训）
- 缺点：新仓库里有一批"口径不统一、风格不一致"的文件

## 决定

**采用 C。**

具体做法：

1. 用 `Copy-Item` 复制，**不打开编辑器、不重排版**
2. 每个 legacy 子目录写一份 `README.md`，说明：源路径 / 迁移日期 / 每个文件是什么 / 值得读哪几段
3. 需要"浓缩版"时**另写一篇**（成品在 `docs/03_knowledge/`：
   `lessons_learned.md` / `factor_zoo.md` / `falsified.md`），开头写 `> 来源：<原文件>`
4. **不在旧文件里修 bug 或改数字**。发现错误 → 在 `docs/03_knowledge/` 加一条"更正"

**一个副作用是故意的**：旧文档里有几处口径混乱
（例如 `STRATEGY_V6_FINAL.md` 说"滚动 12 个月从未为负"，但那是 13:30 + 决策器口径，
11:15 口径下 12.7% 的窗口为负）。**保留这个混乱，并在新文档里指出它**，
比悄悄改掉更有价值 —— 因为"同一句话可以有不同口径"这个教训会随文件一起传下去。

## 代价

1. **`docs/04_legacy/` 里有一批口径不统一、链接会失效的文件**。
   → 缓解：明确声明"legacy 目录内的相对链接不保证可用"；
   要引用时用 `docs/03_knowledge/` 的版本。
2. **新读者可能先读 legacy 而得到过时结论**。
   → 缓解：`docs/04_legacy/README.md` 开头明确"本目录是证据库，不是入门材料"，
   并在 `docs/README.md` 的阅读顺序里把 legacy 放在最后。
3. **仓库体积增加约 250 KB**（含一份 6 MB 的参考 PDF）。可接受。

## 什么时候应该重新考虑

- 如果某份旧文档被新文档完全覆盖且数字一致 → 可以在 legacy 里留一个指针文件，删掉正文
- 如果旧文档的错误开始误导新结论 → 加"勘误表"文件，但**仍不删原文**

## 影响

- `docs/04_legacy/` 下 25 份原始文档 + 5 份索引
- `docs/03_knowledge/` 下 4 份提炼文档
- 主 `README.md` §6 的迁移约定（4 条）
