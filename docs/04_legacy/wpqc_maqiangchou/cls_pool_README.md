# CLS（财联社）历史电报 → 每日票池

从 `CLS历史数据_华福证券.xlsx` 的 `huafu` 表只取 **`time` / `stocks`** 两列，构建 **PIT 安全** 的
「每日票池」：每个交易日 D 的票池，只使用 `as_of(D) = D 14:30` 之前可获知的信息。

- 数据：**5,179** 条电报 / **12,918** 条股票提及 / **3,045** 只代码 / `2025-06-02 15:25` ~ `2026-11-17 09:32`
- 票池：**356** 个交易日（`2025-06-03` ~ `2026-11-17`），日均 **155** 只（默认参数，含历史累积）
- 校验：4 项 PIT 检验全部通过，含「截断不变性」这一决定性检验

---

## 1. 口径

| 概念 | 定义 |
|---|---|
| `as_of(D)` | 交易日 D **14:30:00**（Asia/Shanghai）= 决策/建仓时点 |
| 当日新增 | 电报时间 `∈ (上一交易日 14:30, 当日 14:30]` |
| 历史累积 | 回看 `lookback` 个交易日的「新增」窗口并集，右端同样是当日 14:30 |
| 入池条件 | 当日新增非空 **或** 累积窗口内（不含今日）提及次数 `>= min_hist` |

**PIT 铁律**：进入 D 日票池的任何一条电报，其 `time` 必须 `<= as_of(D)`。
累积统计只回看到 `as_of(D)`，绝不使用 D 日 14:30 之后的信息。

### 为什么是「上一交易日 14:30」而不是「昨天 14:30」

CLS 在周末与法定节假日照常发报。若按自然日「昨天 14:30」切窗，**周末/假日前最后交易日
14:30 之后到周末之间的电报会掉进没有任何票池认领的空档**。实测：

- 自然日规则会漏掉 **123 / 12,918** 条提及（1.0%，涉及 114 只股票）
- 星期分布 `{Fri: 117, Thu: 4, Tue: 2}`，**全部发生在 14:30 之后**

漏掉的正是「周五 14:30 之后 + 周末研报」——次一交易日最相关的那一档信息。
改用「上一交易日 14:30」后，每条电报恰好被一个窗口认领（零丢失、零重复），
周末/长假的电报自然并入下一个交易日（如国庆长假的信息全部进入 `2025-10-09` 的窗口）。

### `cls_daily_pool.csv` 列

| 列 | 含义 |
|---|---|
| `date` / `as_of` / `window_start` | 票池日 / 决策时点（当日 14:30）/ 窗口起点（上一交易日 14:30） |
| `layer` | `fresh` = 当日新增入池；`hist` = 仅靠历史累积入池 |
| `fresh` | 1/0，当日窗口是否有提及 |
| `pool_rank` / `pool_size` | 当日在池内按 `score` 降序的排名 / 当日池容量 |
| `ticker` / `stock` / `exchange` | `002317.XSHE` / `sz002317`（原始写法）/ `XSHE` |
| `n_today` | 当日窗口内提及次数 |
| `n_prev` | 累积窗口内**不含今日**的提及次数（`hist` 入池依据） |
| `n_cum20` | 累积窗口（含今日）提及次数；列名随 `--lookback` 变化 |
| `n_cum5` | 近 5 个交易日提及次数 |
| `score` | 时间衰减加权提及次数 `Σ 0.5^(age/半衰期)`（`age` 以交易日计）；即 `pool_rank` 的排序依据（**仅为排序便利，非验证过的 alpha**） |
| `days_since_last` | 距最近一次被提及的交易日数（0 = 今日） |
| `last_time` / `last_product` | 最近一次提及的时间（**必 `<= as_of`**）/ 所属栏目 |
| `window_complete` | 该日 14:30 是否已过去（False = 数据没覆盖到决策时点） |
| `history_complete` | 回看窗口左端是否不早于数据起点（False = 前 20 个交易日历史被截断） |

## 3. 校验结果（`python verify_pit.py`）

```
A. 截断不变性      8/8 通过
   只喂入 time <= as_of(D) 的电报重算，D 日票池与全量数据完全一致
   （2025-06-09 / 2025-10-09 长假后 / 2026-02-24 / 2026-03-02 /
     2026-06-22 / 2026-09-28 / 2026-11-16 / 2026-11-17）
   → 这是 PIT 的决定性证据：若存在任何前视，截断后结果必然不同

B. 窗口可加性      12,918 = 12,918，未认领 0，落在 as_of 之后 0
   → 每条电报恰好归属一个交易日窗口，零丢失 / 零重复

C. 自然日规则损失  123 / 12,918 (1.0%)，全部为 14:30 之后
   → 佐证「上一交易日」口径的必要性

D. 14:30 边界抽查  2026-11-16 14:16 → 计入当日；2026-11-16 17:14 → 计入次日
```

内建断言（任一失败即报错退出）：电报归属 `as_of >= time`、`last_time <= as_of`、
窗口可加性。另有 `--selftest`：用**完全独立**的暴力实现重算 15 个随机日，逐集合比对。

## 4. 参数与选池规模

```
python build_cls_pool.py --lookback 20 --min-hist 2 --halflife 5 --as-of-time 14:30
```

池容量随参数变化（仅统计 `history_complete=True` 的交易日）：

| lookback（交易日） | min_hist | 日均池容量 | p10~p90 | 其中 fresh |
|---:|---:|---:|---|---:|
| 5 | 2 | 46.4 | 40~53 | 35.2 |
| 10 | 3 | 43.1 | 38~49 | 35.1 |
| 20 | 5 | 39.2 | 34~44 | 35.1 |
| **20** | **2（默认）** | **159.2** | 143~173 | 35.1 |
| 20 | 3 | 72.9 | 64~82 | 35.1 |

默认值是**宽松版**（当日新增全收 + 20 日内被提及 ≥2 次）。若要更集中的票池，任选其一：

- 只要当日新增：`layer == 'fresh'`（≈35 只/日）
- 固定容量：`pool_rank <= 30`（按 `score` 排序，保留池内前 30）
- 收紧累积门槛：`--min-hist 5`（≈39 只/日）

> 若把该池用作策略输入，建议先在样本外确认 `score`/`min_hist` 的方向性；
> `score` 只是排序便利，未做任何有效性验证。

## 5. 已知局限

1. **末日窗口不完整**：`2026-11-17` 的数据只到 `09:32`，但 `as_of` 是 `14:30`。
   该日 140 只票池只反映 09:32 前的信息（`window_complete=False`）。
   数据更新后重跑即可；若要当日实盘使用，请在 14:30 之后重新运行。
2. **前 20 个交易日历史被截断**：`2025-06-03` ~ `2025-06-30` 的 `history_complete=False`，
   这些日子的池实质是「仅新增」。需要干净样本时从 `2025-07-01` 起用
   （356 个交易日中有 335 天两项均完整）。
3. **交易日历**：取自 `wpqc_v6.csv` 的 `TRADE_DT`（已验证无周末，缺失的交易日恰好都是
   中国法定节假日）。`2026-11-04` ~ `2026-11-17` 这 10 天由工作日外延补齐
   （11 月无长假，风险极低）；若延长到其他时段，脚本会在超过 45 天时直接报错，避免凭空假设节假日。
4. **不做可交易性过滤**：未剔除停牌/ST/退市/北交所。这是刻意的——这些过滤本身有
   PIT 风险（需用**当时**的成分与状态），不宜用静态表做。请在回测层用当日快照过滤。
5. **代码映射**：`sz→XSHE`、`sh→XSHG`、`bj→BJSE`（`bj` 为约定映射，项目的
   `bundle/instruments.pk` 里没有北交所标的）。原始 `stock` 列（`sz002317`）始终保留，
   不缺信息。
6. **未做 universe 校验**：3,045 个代码中有 1,031 个不在项目 `instruments.pk` 快照内
   （该快照偏旧，缺少近两年新上市标的），故未用其过滤，避免误杀新股。
7. `n_cum20` 的列名随 `--lookback` 变化（`--lookback 10` → `n_cum10`）。

## 6. 使用示例

```python
import pandas as pd

pool = pd.read_csv("cls_pool/out/cls_daily_pool.csv",
                   parse_dates=["date", "as_of", "last_time"])

# 某一天的票池（已按 pool_rank 排序）
day = pool[pool.date == "2026-11-16"]
top30 = day.nlargest(30, "score")

# 只要当日新增（不含历史累积）
fresh = day[day.layer == "fresh"]

# 回测：每天取前 N 只
picks = (pool[pool.pool_rank <= 30]
         .groupby("date")["ticker"].apply(list))

# 与项目持仓表对齐（TRADE_DT 为 YYYYMMDD 字符串）
pool["TRADE_DT"] = pool.date.dt.strftime("%Y%m%d")
```

典型用法：`2026-11-16 14:30` 之前，用该日票池的 `top30` 在 14:30 之后择时建仓，
持有到次日 14:30 重新评估——口径与窗口完全自洽。

## 8. 策略评估：V8 方案套用到本票池

见 [EVAL_V8_ON_CLS.md](EVAL_V8_ON_CLS.md)。一句话结论：**不建议部署**。

- V8 的选股边际集中在因子横截面最极端的 **0.1% 尾部**（99.9~100% 分位 +13.3bp/次，其余 −2.2bp）；
- 而 CLS 票池被结构性挡在尾部之外（选中个股平均分位 **0.76~0.82**，全市场为 **0.999**），
  因为「有电报」≈「已被关注」，与 V8 要的「冷、低流动性、深度超跌」在同一根轴上反向；
- 323 天全天候口径：V8 原生选股价差 **+50.98%/yr（t=3.46）**，套到 CLS 上只有 **+2.35%（t=0.24）**，
  配对自举 P(无差)=0.008。换只数（0+6 ~ 6+0）、换层（fresh）都救不回来，毛收益全为负。

脚本：`eval_cls_v8.py`（回测 + 推荐清单）、`diagnose_cls_v8.py`（归因诊断）。

```bash
python cls_pool/eval_cls_v8.py            # 回测与推荐清单 → out/cls_v8_*.csv
python cls_pool/diagnose_cls_v8.py        # 归因：尾部凸性 / IC / 配对自举
```
