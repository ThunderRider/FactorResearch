# 研究流程：7 道门

> 本文件是整个 `02_methods/` 的**主文档**。其余文件是它的展开。
>
> 核心问题：**一个因子，凭什么能被写进 `docs/03_knowledge/`、被别的策略引用？**
> 答案：它走完了下面 7 道门，且每一道都留下了可复现的证据。
> 跳过任何一道，它只能停在 `status: draft`。

---

## 0. 全景

## 门 1 · 假设：先写"什么会证明我错了"

**产物**：`research/<direction>/idea.md`

必须回答四问，缺一不可：

```markdown
1. 经济逻辑：谁在被迫交易？谁的信息没被定价？
   （不能是"因为 IC 是负的"——那是观察，不是逻辑）

2. 精确构造：字段 → 公式 → 方向。可直接翻译成代码。

3. 可证伪的预测：如果这个逻辑成立，除了 IC 之外还应该看到什么？
   例："若它真是流动性折价，则应满足：① 正交化 log(成交额) 后 IC 保留 >60%；
       ② 在成交流更低的股票上更强；③ 隔夜段 IC 强于早盘段。"

4. 失败判据（提前写死）：
   例："若组合层净年化提升 < 2pp，或正交后 IC 符号翻转 → 丢弃，不再调参。"
```

**第 4 条是本仓库最反直觉、也最重要的一条。**
在没有失败判据的情况下去跑实验，等于允许自己在看到结果后再决定"什么算成功"——
这就是数据挖掘的定义。

> **真实教训**：旧项目测 MAX 彩票因子（Bali et al. 2011），IC −0.0513，四年全负，看起来很强。
> 但同时发现它与 20 日波动率相关 **0.874**——它就是波动率的马甲。
> 如果一开始写了"失败判据：与现有暴露相关 > 0.7 即丢弃"，能省下 9 组实验。

## 门 2 · 登记：跑之前先开账

**产物**：`registry/factors.yaml` 加一条 + `registry/trials_log.csv` 加一行

```yaml
# registry/factors.yaml
- id: vol_ratio_1430
  status: candidate          # draft → candidate → active → watch → retired → rejected
  ...
```

```csv
# registry/trials_log.csv
run_id,date,hypothesis,object,params,sample,metric,value,passed,notes,script,git_sha
20261120-vol_ratio,2026-11-20,同时刻量比在同池内有负向预测力,vol_ratio,w20,2020-01~2026-10,mean_ic,,tbd,,run.py,abc1234
```

**注意 `value` 先留空、`passed` 填 `tbd`。** 先记账再跑，是为了防止
"结果不好就不记了"——而那恰恰是最需要记的一类。

**为什么这一步不能省**：`N`（试验次数）是所有统计推断的分母。
旧项目最终清点出 N≈110（含随机抽样超过 900），但因为没有事前记账，
`σ(SR)` 无法确定，DSR 只能给敏感性网格 **0.51~0.77**——
永远无法回答"这个夏普里有多少是搜索的产物"。

> 量化防过拟合系列的原话：**"如果你没有记录 N，你就永远无法知道你的策略是不是一个谎言。"**

## 门 3 · 因子层：IC 显著，且经得起重叠窗口的修正

**产物**：`artifacts/results/<run_id>/ic_summary.csv`、`decile.csv`

必报项（缺一不可）：

| 指标 | 为什么必须 |
|---|---|
| **RankIC 均值** | 基本预测力 |
| **NW(20) t 值** | 重叠窗口下 naive t 会高估。旧项目 `vol_ratio` naive t=−14.6 → NW t=−11.4 |
| **有效样本 N_eff** | 同上 |
| **块自举 95% CI** | 区间必须不含 0 |
| **逐年 IC** | 单年驱动 = regime 依赖 |
| **分层单调性（q1..q10）** | IC 是线性相关，分层能看出非线性/尾部效应 |
| **覆盖率** | 覆盖率 30% 的因子，IC 再好也只能用在一小撮票上 |
| 与现有因子的**相关矩阵** | 提前发现马甲 |

**门 3 的判定线**（可调，但改了要记账）：

```
|NW t| >= 3.0        且
块自举 95% CI 不含 0  且
逐年同向（至少 3/4 年）且
有效独立样本 >= 400 天
```

⚠️ **警告：门 3 通过 ≠ 因子有用。** 旧项目踩过两次：

- MAX 因子：IC 漂亮、四年全负、与波动率 0.874 → 组合层 9 种用法全部变差
- `amihud`：IC +0.033、NW t=+5.5、置换重要性最强（ΔSharpe 0.98）→ **正交化后 IC 符号翻转**

**所以门 3 只是入场券，真正决定生死的是门 4 和门 5。**

## 门 4 · 独立性：它是新信息，还是旧暴露换了张皮？

**产物**：`orth.csv`、`permutation.csv`

两件事，一件都不能少：

### 4.1 正交化（Is it new?）

对控制变量做截面回归，用**残差**重算 IC 与组合收益：

```python
controls = ['log_amt20', 'log_mktcap', 'vol_20d', 'ret_20d']   # 见 configs/evals/default.yaml
from factorlab.eval import orth
resid = orth.orthogonalize(panel, factor, controls, by=('pool', 'date'))

# 或者一条命令看保留率
# python -m factorlab.eval.orth --panel <panel> --factors <f> \
#     --controls log_amt20 vol_20d ret_20d --label ret_1445_next_1115
```

判定：**正交后 IC 保留率 > 60%**。

> **真实数据**：`amihud` 对 log 成交额正交后 IC 从 **+0.0103 变成 −0.0315（符号翻转）**，
> 对"额+波动+反转"正交后净年化从 9.59% 掉到 **0.52%**。
> 结论：它几乎完全是"低流动性 + 高波动 + 超跌"的合成包装，**不存在独立的非流动性溢价**。
>
> 对比：`vol_ratio` 对"log 额 + 波动"正交后 IC 保留 **96%**、净年化只掉 0.55pp。
> **这才是真因子。**

### 4.2 置换重要性（Does it matter?）

把该因子的截面值随机打乱，其余不变，重跑选股与回测，看收益下降多少：

```
ΔSharpe = SR(基准) − SR(打乱该因子)
```

判定：**ΔSharpe > 0.10**。

**必须同时跑一个对照**：把一槽换成**纯噪声**（随机数），看它造成多少损失。

> **为什么**：旧项目测出"打乱 amihud，净年化从 +9.6% 掉到 −4.0%"（ΔSR 0.98），
> 但同时"噪声占一槽"的对照也掉了 ΔSR 0.67。
> **所以"打乱 amihud 掉 13.6pp"里，约有 9.5pp 是"多一列噪声的代价"，
> 净信息量只有约 4pp。** 不给对照就会系统性高估单因子贡献。

## 门 5 · 组合层：跨过盈亏平衡线

**产物**：`backtest.csv`、`fragility.csv`

**看什么**（按重要性排序）：

| 指标 | 为什么比"年化收益"重要 |
|---|---|
| **每单位敞口的日收益** vs 盈亏平衡线（0.200%） | 把选股质量与仓位大小分开。仓位只改变成本 |
| **最大回撤 + 恢复时间** | 决定"能不能活着等到它生效" |
| **分年收益** | 单年驱动 = regime 依赖 |
| **收益集中度**（前 10 天贡献占比） | 前 10 天贡献 > 50% 意味着"其实只赚了 10 天" |
| **换手率与名称重合度** | 决定容量与执行难度 |
| **成本敏感性三档** | 成本翻倍时还剩多少 |

**门 5 的判定线**：

```
每单位敞口日收益 > 0.200%（盈亏平衡线）+ 至少 0.05pp 安全垫
成本 0.15%/边 时净年化仍 > 0
```

> **为什么是"单位敞口日收益"**：旧项目 V1 每单位敞口 0.196%，只比 0.200% 低 0.4bp，
> 结果净年化 −0.9%；V3 是 0.315%，净 +9.4%。
> 报告"年化 13.69%"会让人以为赚了很多，可是**成本吃掉了 20pp**。

### 5.1 脆弱性曲线（必做）

剔除最好的 k 个交易日，看还剩多少：

| k | 0 | 1 | 3 | **5** | 8 | 10 | 20 |
|---|---|---|---|---|---|---|---|
| V3 净年化 | 9.44% | 6.29% | 3.01% | **−0.02%** | −3.46% | −5.28% | −12.35% |

判定：**去掉最好 5 天后仍 > 0**。

旧项目 V3 **在第 5 天归零**。这不是缺陷，是这类策略的结构特征——
但**必须写进材料**，否则"年化 13.69%"会被当成点估计。

### 5.2 块自举

`block=20, n=3000`，给出年化与 Sharpe 的置信区间。

> 旧项目 V3：年化 95% CI = **[−7.3%, +28.9%]**，P(年化<0) = **14.8%**。
> **在"3.2 年、单一路径、日频全换"这个数据预算下，+9.4% 与 0 在统计上还没被分开。**
> 这不是策略的错，是样本长度的限制——但不说出来就是误导。

## 门 6 · 审计：惩罚"你试了多少次"

**产物**：`dsr.csv`、`pbo.csv`、`purge.csv`、`lookahead_report.txt`

这四件事是"审计层"，旧项目全部缺失（这是它最诚实的自我批评）。新仓库默认要做。

| 工具 | 回答什么问题 | 门槛 |
|---|---|---|
| **前视体检**（[`lookahead_audit.md`](lookahead_audit.md)） | 有没有作弊？ | 修正后跌幅 < 0.5pp |
| **DSR**（Deflated Sharpe Ratio） | 这个夏普扣掉"搜索次数"还剩多少？ | **> 0.95** |
| **PBO / CSCV** | "用 IS 挑出的冠军，去 OOS 会不会排到中位数以下"？ | **< 0.5** |
| **Purging / Embargo** | OOS 边界是否共享了信息？ | 禁运 ≥ 最大特征窗后仍成立 |

### 6.1 DSR：最容易被忽略的一项

```
DSR = PSR( SR*, T, skew, kurt )  其中 SR* = 被 N 次试验的期望最大值"打折"后的夏普
```

旧项目的账：

| N \ σ(SR) | 0.15 | 0.25 | 0.35 |
|---|---|---|---|
| 1（不惩罚） | 0.896 | 0.896 | 0.896 |
| 24 | 0.767 | 0.646 | 0.509 |
| **120（接近真实）** | 0.714 | **0.540** | 0.358 |

**不惩罚时 PSR=0.90（"看起来显著"）；按 N≈120 记账，DSR 落到 0.54。**
门槛是 0.95。这就是"我们还没到可上线"的量化表述。

### 6.2 PBO：把"选参流程"本身当作被检验对象

把样本切成 S=10 块，穷举 10 选 5 的对称组合（252 条路径），
每条路径上"用 IS 选出的冠军，去 OOS 排位"：

```
PBO = IS 冠军在 OOS 落到后 50% 的概率
```

旧项目：决策器 **PBO = 56.3%** → 等于抛硬币 → 正式判"不通过"。
**注意**：PBO 检验的不是"信号有没有用"，是"你的选参流程可不可信"。
参数冻结的策略（不重训、不选参）可以跳过 PBO，但**必须在材料里说明为什么跳过**。

### 6.3 Purging / Embargo：重叠窗口的隐形泄漏

```python
# 分位窗口是 expanding(120)
disp_pct = disp.expanding(120).apply(...)
```

这意味着"样本外"的前 120 天与"样本内"共享信息。禁运 120 天后重算：

| 切分点 | 禁运 | OOS SR（真实规则） |
|---|---|---|
| 2024-06-28 | 0 | 1.410 |
| 2024-06-28 | **120** | **0.865** |
| 2025-06-30 | 0 | 0.969 |
| 2025-06-30 | **120** | **0.492** |

**"样本外 99.1 分位"这个结论，在禁运后不成立。** 旧项目据此撤回了它。

**规则**：任何 IS/OOS 切分，必须写明 **切分日** 与 **禁运长度**；
禁运长度 ≥ 该策略用到的最大特征窗。

## 门 7 · 判决：留 / 观察 / 丢，并写下退役条件

**产物**：`research/<direction>/conclusion.md` + 更新 `registry/factors.yaml`

三种状态，措辞必须精确：

| 状态 | 含义 | 允许的说法 |
|---|---|---|
| `active` | 通过全部门，可进策略 | "有独立信息，组合层贡献 X pp，样本外待观察" |
| `watch` | 部分通过，证据不足 | "样本内有效但样本外未验证，**不得计入业绩预期**" |
| `rejected` | 任一门实质不通过 | "已证伪，不要再试"，写清死因 |

### 必须写"退役条件"

```yaml
retire_if:
  - 连续 2 个季度 IC 绝对值 < 全样本一半
  - 正交后 IC 保留率 < 40%
  - 与新增因子的相关 > 0.8
```

> **为什么必须提前写**：旧项目 `ret_20d` 的 IC 从 −0.052 逐年衰减到 −0.029（2026 年腰斩），
> 但**系统里没有任何"因子退役"机制**，所以它一直在用。
> 非平稳性是必然的，退役规则是唯一的应对。

### 判决的语言规范

| ❌ 不要写 | ✅ 应该写 |
|---|---|
| "效果不错" | "小盘池 IC −0.048，NW t=−11.4，分层 q10−q1 = −38.5bp/日" |
| "样本外显著" | "2025-07 起样本外，禁运 120 日，Sharpe 0.49（切分日 2025-06-30）" |
| "因子有效" | "对 log 成交额正交后 IC 保留 96%，组合层贡献 +1.1pp" |
| "可以上线" | "当前状态 watch：样本外仅 81 个交易日，建议纸面跟踪 3–6 个月" |

## 附：一句总结

> **门 3 决定"有没有信号"，门 4 决定"是不是新信号"，门 5 决定"能不能赚钱"，
> 门 6 决定"是不是运气的产物"，门 7 决定"以后还要不要看它"。**
>
> 大多数人只做门 3。这就是为什么大多数因子研究不能落地。
