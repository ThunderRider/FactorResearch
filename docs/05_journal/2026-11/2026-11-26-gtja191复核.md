## 关于第 1 条：为什么是修 bug 而不是改口径

`composite()` 只认 `<col>_z` 后缀的列。修复前代码把 `__noise__`（裸 `N(0,1)`）直接塞进
`composite(frame, weights)`，会抛：

```
KeyError: 缺少标准化列 __noise___z，先调用 zscore()
```

也就是说**那段噪声对照从来没跑通过**，不存在"改坏了历史结论"。修复前后实测（GTJA 第一批，base Sharpe −1.5878）：

| noise 口径 | Sharpe | 10 次组内 std |
|---|---|---|
| 不标准化（修复前那条路） | −1.4432 | 0.1014 |
| 按组标准化（修复后） | −1.4364 | 0.0955 |

均值差 **0.007**（0.07 个标准差），标准化只是把对照的抽样噪声压低 6%。**结论不变。**

## 关于第 3 条：噪声对照比基准还好，说明什么

```
base                 -1.588
shuffle:gtja_117     -1.507   打乱它，组合反而变好
noise_control        -1.436   换成纯噪声，组合更好
```

`net = delta − noise_delta` 这个公式只在"噪声占一槽会让组合变差"时才有意义。
这里 `noise_delta < 0`，公式会把三个因子的净贡献一律加上 0.14——所以
**`net ΔSharpe` 0.19 / 0.23 / 0.04 不能引用**。正确读法是：三个因子的边际贡献
都与一个噪声槽不可区分，其中 `gtja_117` 明确为负。

## 一个环境层面的坑（顺带发现）

仓库的 `portfolio` / `eval` 代码依赖 `include_groups=`（pandas ≥ 2.2），
但 WSL 里唯一的 pandas 环境 `rq` 只有 **2.0.3** —— 跑 `portfolio/backtest.py` 会直接
`TypeError: _one() got an unexpected keyword argument 'include_groups'`。

这次能用，是因为 codex 用的是 Windows 侧 `D:\MINIFORGE\python.exe`（pandas 2.3.3），
`build_panel.py` 里那句 `DATA = Path(r"\\\\wsl.localhost\\...")` 就是痕迹。

**影响**：任何人用 `rq` 环境跑 `run.py` 都会在组合层崩。已在 `pyproject.toml` 与
`requirements.txt` 把底线抬到 `pandas>=2.2`，但这只解决了声明，**没有解决 WSL 侧缺环境**。
要彻底解决，需要给 `rq` 环境升级 pandas（会影响 rqdatac 兼容性，需单独验证）。
