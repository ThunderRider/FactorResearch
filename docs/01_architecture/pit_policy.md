# PIT 政策（Point-In-Time）

> **铁律**：任何进入 T 日决策的字段，其"最后可知时点"必须 `<= as_of(T)`。
> 违反这条，回测数字就是**偏差**而不是**运气**——偏差不会随样本变长而收敛。

---

## 1. 为什么这条单独成文

旧项目 wpqc 做过一次非常完整的因子研究，最后审计出的**唯一一个"可证伪偏差"**是：

```
tradable_mask 用 amt20 > 5e7 过滤
amt20 = 含当日 15:00 收盘的 20 日均成交额
决策发生在 14:45
→ 决策时点用了 15 分钟之后才存在的信息
```

后果：V3 净年化虚高 **1.66pp**、**6.02% 的选股**发生变化、V6 虚高 1.97pp。

**为什么影响远大于"0.92% 的股票受影响"**：过滤器改变的是**整个候选池的构成**，
池内 z-score 的均值/标准差随之改变，**所有股票的排名都会漂移**。
前视不是"少数样本被污染"，是"整把尺子偏了"。

所以 PIT 不是"检查一下有没有未来函数"这种一次性动作，而是**每个字段的强制属性**。

## 2. 三个时间概念

```
         T-1 收盘           as_of(T) = T 14:30        T 15:00
            │                      │                    │
   ─────────┼──────────────────────┼────────────────────┼─────►
            │                      │                    │
      T-1 的完整信息         决策/建仓时刻          T 日收盘
      （全部可知）           （只能用左侧信息）     （晚于决策，不可用）
```

| 概念 | 定义 | 例子 |
|---|---|---|
| `as_of(T)` | 决策时点，默认 `T 14:30` | 尾盘选股 |
| **时点值** | 某一瞬间的值，`value(t)` 在 `t <= as_of` 时可知 | `c1430`（14:30 收盘价） |
| **区间累计值** | `[t0, t1]` 内的累计，只有 `t1 <= as_of` 才可知 | `v1430`（14:00–14:30 的量）✅<br>`day_vol`（当日全天量）❌ |

**唯一的判断方法**：问"这个数字在 14:30 那一秒算得出来吗？"

- `c1430` → 算得出 ✅
- `v1430`（这一根 bar 的量）→ 算得出 ✅
- `day_amt`（当日全天成交额）→ **算不出** ❌（15:00 才知道）
- `amt20`（含今日的 20 日均额）→ **算不出** ❌
- `amihud`（用今日收盘价与今日成交额）→ **算不出** ❌ → 必须 `shift(1)`
- `high_20d`（20 日最高）→ 若含今日盘中，算得出（截至 14:30 的最高）✅

---

## 3. 处理方式（只有三种，没有第四种）

| 情况 | 处理 | 说明 |
|---|---|---|
| 字段在 `as_of` **之后**才产生 | **`shift(1)`**（用 T-1 值） | 默认做法 |
| 字段在 `as_of` **之前**已完整 | 直接用 | |
| 字段**跨越** `as_of`（如"当日至今累计"） | **显式构造 as_of 版本**，如 `v_upto_1430` | 不要拿全天值凑合 |

**绝对禁止**："先用当日值，反正影响只有 1%。"
旧项目当年就是这么想的，代价是 1.66pp。

## 5. 三个高频事故

### 5.1 幸存者偏差：用最新成分回测历史

```python
# ❌ 错误：用今天的沪深300成分股，回测 2020 年
codes = rqdatac.index_components('000300.XSHG')          # 今天的
bars  = rqdatac.get_price(codes, start='2020-01-01', ...)

# ✅ 正确：逐日取当日成分
for d in trading_days:
    codes = rqdatac.index_components('000300.XSHG', date=d)
```

后果不是"错一点"，是**系统性高估**：活到今天的公司本来就是赢家。
旧项目为此专门构建了 `cn_mac_pit_universe_*.parquet`（每日快照长表）。

### 5.2 用"含今日"的滚动统计

```python
# ❌
amt20 = day_amt.rolling(20).mean()               # 含今日 15:00
vol20 = daily_ret.rolling(20).std()              # 含今日
# ✅
amt20 = day_amt.rolling(20).mean().shift(1)
vol20 = daily_ret.rolling(20).std().shift(1)
```

**注意**：`shift(1)` 要加在 `rolling` **之后**，不是之前。
`rolling` 再 `shift` = "过去 20 日（不含今日）"；`shift` 再 `rolling` = "错位的 20 日"，两者不同。

### 5.3 缺失值被静默跳过

```python
# ❌ groupby.sum() 会跳过 NaN，等于"按 0% 收益成交"
m['w_ret'] = w * ret
daily = m.groupby('date')['w_ret'].sum()

# ✅ 显式记账
m['is_missing'] = ret.isna()
daily = m.groupby('date').agg(gross=('w_ret','sum'), n_miss=('is_missing','sum'))
```

旧项目 V6 有 24 笔（0.55% 权重）停牌日被当作 0% 收益——方向性上**回测被高估**。
量级小，但它属于"必须修好再谈容量"的项。

## 6. 审计怎么做（自动化，不靠自觉）

```bash
# 每次回测前必跑
python -m factorlab.audit.lookahead --config configs/data.yaml --panel <panel>
```

它做四件事：

1. **PIT 表覆盖检查**：panel 里每个因子列，能否在 `field_pit.yaml` 找到来源字段？
   找不到 → 报错（不许有"来路不明的列"）。
2. **shift 复算**：对标记 `needs_shift: true` 的字段，用原始 curated 数据重算
   "含今日"与"不含今日"两版，比较 panel 里存的是哪一版。不一致 → 报错。
3. **转折点检验**（最有力）：
   > 只用 `<= as_of(T)` 的数据重算 T 日决策，结果必须与全量数据算出的**完全一致**。
   这条叫**截断不变性**（truncation invariance），旧项目 cls_pool 用它做过 8/8 通过的决定性检验。
   只要有任何前视，截断后结果必然不同。
4. **口径差异量化**：把"修正前 / 修正后"的净年化、选股变化比例列出来。
   **判定线：修正后跌幅 < 0.5pp 算通过；> 1pp 说明有真问题。**

- [ ] 若用了滚动统计，`shift` 加在 `rolling` 之后
