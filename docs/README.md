# 文档地图

> 一条规则：如果一个结论值得被别人引用，它就必须在这里有一席之地，而不是躺在 notebook 的第 37 个 cell 里。

## 文档的三类，别混

| 类型 | 特征 | 放哪 | 寿命 |
|---|---|---|---|
| **方法（Method）** | 讲"怎么做才对"，与具体因子无关 | `02_methods/` | 长期，慢慢演进 |
| **知识（Knowledge）** | 讲"我们已经知道了什么"，带数字 | `03_knowledge/` | 长期，会更新 |
| **记录（Record）** | 讲"某天我们做了什么、看到了什么" | `05_journal/` / `04_legacy/` | **永久冻结，只追加** |

把记录写进知识里是常见错误：一次试验的偶然结果，不该变成"常识"。
知识条目必须写明**证据出处**（哪个 run / 哪个文件 / 哪张表），否则它只是记录。

## 命名约定

```
NN_topic.md              两位序号决定阅读顺序（不是重要性）
<project>_<topic>.md     legacy 档案用项目前缀，便于 grep
YYYY-MM-DD_<slug>.md     journal 用日期前缀，天然按时间排序
NNNN_<decision>.md       ADR 用四位编号
```

## 反模式（这些不该出现在本目录）

- ❌ 只有结论没有数字的文档（"效果不错"）
- ❌ 数字没有出处的文档（说不出哪次 run 得来的）
- ❌ 把 notebook 导出的输出直接贴进来（请写成人能读的表）
- ❌ 同一件事在两个文件里各写一版（选一处，另一处链接过去）
